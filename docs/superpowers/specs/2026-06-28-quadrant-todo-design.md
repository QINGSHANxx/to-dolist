# 四象限 Todo 应用 - 设计规格

## 概述

将现有 Todo 应用改造为艾森豪威尔矩阵（四象限）布局。用"重要"和"紧急"两个布尔维度替代原有的"低/中/高"优先级，任务按象限自动分组显示在 2×2 网格中。

## 数据模型

移除 `priority` 字段，新增 `important` 和 `urgent` 两个整数字段（0 或 1）。

```sql
CREATE TABLE todos (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT NOT NULL,
  completed INTEGER DEFAULT 0,
  important INTEGER DEFAULT 0,
  urgent INTEGER DEFAULT 0,
  due_date TEXT,
  sort_order INTEGER DEFAULT 0,
  created_at TEXT DEFAULT (datetime('now'))
);
```

数据库迁移：创建新表，迁移旧数据（priority high → important=1 urgent=1，medium → important=1 urgent=0，low → important=0 urgent=0），删除旧表，重命名新表。

## 四象限定义

| 象限 | 条件 | 含义 | UI 标签 | 颜色 |
|------|------|------|---------|------|
| Q1 | important=1, urgent=1 | 立即做 | 🔴 立即做 | #C41E3A（朱砂红） |
| Q2 | important=1, urgent=0 | 安排做 | 🔵 安排做 | #2D5F8A（靛蓝） |
| Q3 | important=0, urgent=1 | 委托做 | 🟡 委托做 | #B8860B（暗金） |
| Q4 | important=0, urgent=0 | 尽量删 | ⚪ 尽量删 | #6B6B6B（砚灰） |

## API 变更

### 修改端点

- `POST /api/todos` — 请求体字段从 `priority` 改为 `important` + `urgent`
- `PUT /api/todos/:id` — 同上

### 新增端点

- `GET /api/todos/stats` — 返回各象限任务数和完成率

响应格式：
```json
{
  "total": 12,
  "completed": 5,
  "quadrants": {
    "q1": { "total": 3, "completed": 2 },
    "q2": { "total": 4, "completed": 1 },
    "q3": { "total": 2, "completed": 1 },
    "q4": { "total": 3, "completed": 1 }
  }
}
```

## 前端 UI

### 整体布局

页面顶部为标题和统计摘要，中间为 2×2 网格，底部为添加任务区。

```
┌─────────────────────────────────────────┐
│  待办                                    │
│  共 12 项 · 已完成 5 项                   │
├─────────────────────────────────────────┤
│  ┌─────────────────┬─────────────────┐  │
│  │ 🔴 立即做 (3)    │ 🔵 安排做 (4)    │  │
│  │  · 买菜          │  · 读书          │  │
│  │  · 修电脑        │  · 学英语        │  │
│  ├─────────────────┼─────────────────┤  │
│  │ 🟡 委托做 (2)    │ ⚪ 尽量删 (3)    │  │
│  │  · 回邮件        │  · 刷手机        │  │
│  └─────────────────┴─────────────────┘  │
├─────────────────────────────────────────┤
│  ┌─────────────────────────────┐        │
│  │ 写下来，才不会忘...          │        │
│  └─────────────────────────────┘        │
│  [重要 ✓] [紧急 ✓]           [添加]     │
└─────────────────────────────────────────┘
```

### 任务卡片

每个象限内的任务显示：标题、截止日期（如有）、完成复选框。悬停显示编辑和删除按钮。点击复选框标记完成，完成后任务变灰并移至该象限底部。

### 输入区域

替代原有的下拉框，改用两个独立开关按钮：

- 「重要」开关：默认关闭，点击切换
- 「紧急」开关：默认关闭，点击切换

开关样式：方形按钮，选中态为对应象限颜色。

### 响应式

- 桌面：2×2 网格
- 平板：2×2 网格，缩小间距
- 手机：垂直堆叠为 4 个区块

## 筛选功能

保留原有的"全部/待做/已完成"筛选，但改为在每个象限内部生效。即：切换筛选时，四个象限同时过滤。

## 实施步骤

4. 更新前端 HTML — 输入区改为双开关，添加统计摘要
5. 重写前端 CSS — 2×2 网格布局，象限配色

## 验证方法

1. 启动服务器，访问 http://localhost:3000
2. 添加 6 条任务，分别设置不同的重要/紧急组合
3. 验证任务自动分配到正确的象限
4. 标记完成，验证任务变灰并移到象限底部
5. 切换筛选，验证四个象限同时过滤
6. 刷新页面，验证数据持久化
7. 手机尺寸下验证垂直堆叠布局
